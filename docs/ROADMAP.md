# Roadmap

What each release added, and what is still to come. Per-release detail —
including every diagnostic code as it arrived — is in the
[CHANGELOG](../CHANGELOG.md); what works today is the
[README](../README.md).

| | Release | What it adds |
| --- | --- | --- |
| ✅ | **Preview** | Semantic colour, live diagnostics, completion, hover, outline, folding, snippets |
| ✅ | **Navigation** | Go to definition and type definition · Find all references · Highlight occurrences · Workspace symbol search · Safe cross-file rename of multi-word names · "Which rule derives this attribute?" |
| ✅ | **Validation** | The full diagnostics catalogue — type compatibility, unit convertibility, rounding and precision, empty-value (`leeg`) policy, timeline granularity, distribution and decision-table rules — with quick fixes, plus signature help |
| ✅ | **Formatting & ergonomics** | Formatting that changes whitespace and nothing else · CodeLens reference and derivation counts · Inlay hints for inferred datatypes and units · Smart selection expansion · Links in comments |
| ✅ | **Workbench** | A RegelSpraak view container with a Model Explorer tree · Call hierarchy over rule dependencies · Type hierarchy over object types and their extensions · A read-only model view of a file · A preview for decision tables · Language server status in the status bar |
| ✅ | **Test language and execution** | `*.test.rgs` testsets as part of the language: colour, checks (`RS951`–`RS958`), outline, folding, formatting, completion, hover, and navigation and rename that cross between a testset and the model it tests · Running them in the Test Explorer, with failures as diffs · Running a testset, a testgeval or a single rule from a link in the text · The outcome and the derivation trace as a panel beside the model, with click-through to the rule behind every value · `Regelgroep <naam>` |
| ✅ | **Debugging a run** | Step through a run with <kbd>F5</kbd>, one rule × instance at a time · Breakpoints on a rule or on a `Verwacht` line, optionally held to one instance · The situation, the parameters and the rekendatum at every stop · Watch, the Debug Console and hover evaluating an expression in the paused scope · Why a rule did *not* fire · Every value walkable back to the rules and inputs behind it · Five further checks (`RS114`–`RS116`, `RS615`, and `RS101`/`RS102` inside decision tables) |
| ✅ | **Importing from ALEF, and the arithmetic behind a value** | The provision a rule renders, as a `// Bron:` citation a hover follows · Plurals a model need not spell out · **Importeren uit ALEF**: an ALEF project read and written out as RegelSpraak text, with a report of everything it could not translate · An apostrophe in a name, and three more words a name may contain · The arithmetic inside a rule — in the trace, in Watch, and under <kbd>F11</kbd> |
| ✅ | **Tables from outside the model, and the way into a run** (current) | `Gegevensbron`: an externally supplied table declared by its shape, as an extension beyond v2.3.0 · A key lookup, `het tarief uit de tarieftabel bij …`, typed and checked (`RS121`–`RS125`) · The content bound in the testset — a miniature inside a testgeval, or a delivery on disk through a manifest, with the run naming what it read (`RS961`–`RS963`) · Parameters on a timeline (`RS705`, `RS960`) · Rules that derive their values from each other reported as a loop (`RS616`) · A kenmerk's timeline read by the model · A testgeval without expectations reported as skipped · **Leg uit**: one gesture from a value to the derivation behind it — from the `Verwacht` line that just failed, from the editor (<kbd>Alt</kbd>+<kbd>E</kbd>) or from the palette · A verdict list where no rule wrote the value, saying what each rule that could have did instead · A decision table's write naming the rows it tried and the row that decided · Aggregations that open into the elements behind them, largest first · Time-dependent values drawn as a dated timeline · **Vergelijk met vorige uitvoering**, in the panel or as a diff of two runs · The trace fetched as rows are opened rather than shipped whole |
| ⬅ | **Optional extras** | Scenario notebooks · Recursive rule groups (§9.10) · Test coverage over a model · Bulk evaluation over external tables (parked: a requirement of a future runner and its compiler, not of the editor) — each still to be decided on |

**Export to ALEF is deliberately not in scope.** ALEF stores a model as an MPS project, and an MPS project is not a folder of model files: the XML holds an abstract node tree whose concepts and references mean something only inside a solution that declares the languages it is written in, at the versions it is written in, and imports the models it points at. That scaffolding belongs to an ALEF release rather than to the file format an outside tool can observe, so writing it from the outside means encoding assumptions about somebody else's environment that go stale when that environment moves.
